# Executive-friendly UX Redesign v1

**상태:** frontend 전용 재설계 · backend/product semantics 무변경 · 기능 추가 0
**대상 사용자:** 40~50대 온라인 판매회사 대표 / 영업·CS 책임자 (비기술)
**앞선 패키지:** Demo UX Polish v1(`b5abbe20`)의 수정은 전부 유지한다. 이 문서는 그 위에서
**정보 구조와 읽는 순서**를 다시 정한다.

## 1. 사용한 UI/UX skill

`ui-ux-pro-max` (plugin `ui-ux-pro-max-skill` v2.11.0, 로컬 설치본). 함께 있는 `design` 서브스킬은
로고·CIP·배너·슬라이드 생성기라 이 작업 대상이 아니다.

**무엇을 채택했고 무엇을 버렸는지 — 그대로 적는다.**

`--design-system`은 이 제품에 맞지 않는 답을 냈다. 질의 「commerce operations dashboard SME seller
task inbox non-technical older adults」에 대해 돌아온 것은 **랜딩 페이지 패턴**(Real-Time /
Operations Landing — Hero, Key metrics, How it works, Start trial CTA), 스타일 **Exaggerated
Minimalism**(`font-size: clamp(3rem,10vw,12rem)`, `font-weight: 900`), 서체 **Fira Code / Fira
Sans**, accent `#DC2626`였다. 이 제품은 랜딩 페이지가 아니라 로그인 뒤의 운영 화면이고, 서체·팔레트
교체는 이번 지시의 「새 디자인 프레임워크 도입 금지」와 정면으로 어긋난다. **그래서 이 출력은
쓰지 않았다.**

실제로 쓴 것은 `--domain ux` 가이드라인이며, 아래 다섯 개가 이번 수정의 근거가 됐다:

| 규칙 | severity | 이 제품에서 위반된 지점 |
|---|---|---|
| Contrast Readability / Color Contrast (4.5:1) | High | `muted` `#6B7684`가 `canvas` `#F2F4F6` 위에서 **4.19:1 — 기준 미달**. 화면 대부분의 보조 텍스트가 여기 해당 |
| Color Only | High | 「연결 확인 3」·수집 상태 pill이 색 계열로만 구분 |
| Font Size Scale | Medium | `xs`=12px / `sm`=14px가 Tailwind 기본값 그대로. base만 17px로 키워 둬 **본문과 메타의 간격이 벌어짐** |
| Line Height (1.5~1.75) | Medium | `sm` 기본 line-height 1.43 |
| Number Formatting | Low | 채널별 표의 `2 / 26`, `0 / 0` 복합 숫자 |

`--domain product`는 이 제품을 "SaaS (General) / Smart Home·IoT Dashboard"로 매칭했고 권고는
"Data-Dense + Real-Time Monitoring". **이것도 채택하지 않았다** — data-dense는 지금 이 화면이 이미
겪고 있는 문제이지 목표가 아니다.

| 화면 | 지금 무슨 상황인가 | 문제가 있는가 | AI가 뭘 해뒀나 | 뭘 누르면 되나 |

| 홈 | △ 숫자 6개가 같은 크기 | ✗ 「문의 2」와 「미답변 문의 26」이 나란히 | ✗ "1건 있어요"만, 무슨 일인지는 안 보임 | ✗ 동일 강조의 CTA 5개 |

## 4. 기존 UI가 어려웠던 핵심 원인 — 네 가지

**원인 1 — 모든 것이 같은 크기다.** 홈의 KPI 6개는 폭·높이·글자 크기가 동일하고, 그 아래 「지금
눈여겨볼 것」 3행도 서로 같으며, 우측 [AI에게 묻기]가 3번 반복된다. 강조가 균등하면 강조가 없다.
40~50대 사용자는 스캔할 진입점을 못 찾고 **왼쪽 위부터 순서대로 읽기 시작한다** — 그 순간 30초는
끝난다.

**원인 2 — 정직함이 설명문으로 표현됐다.** 이 제품의 강점(무엇을 모르는지 말한다)이 매번 **회색
작은 문장**으로 나온다: 「이 문의는 상품과 연결되지 않았고, 운영 정책·과거 답변에도 해당 내용이
없어 문의 내용만 보고 쓴 초안입니다」. 정보는 맞지만 형식이 틀렸다 — 이건 **할 일**이지 각주가
아니다.

**원인 3 — 도구가 일보다 앞에 있다.** 문의 화면의 첫 열은 필터 11개, 리뷰 화면은 본문 전에 크롬
7블록, 문의 상세는 필터+목록이 폭의 62%를 쓰고 정작 「고객 질문 + AI 답변」이 38%에 눌려 있다.

**원인 4 — 회색이 안 읽힌다.** `muted` 토큰이 `canvas` 배경에서 **4.19:1**로 WCAG AA 미달이고,
보조 텍스트의 절대다수가 이 조합이다. 노안이 시작되는 연령대에서 이건 "정보가 적다"가 아니라
"정보가 없다"로 읽힌다.

## 5. 무엇을 제거할 것인가 (product-owner 관점)

기능은 그대로 두고 **화면에서 뺀다.**

| 제거 | 어디서 | 왜 |
|---|---|---|
| KPI 카드 3개(매출·문의·리뷰)의 카드 지위 | 홈 | 6개 동급 → 3개 primary + 보조 1줄 |
| `†` 다거 각주와 그 범례 문장 | 홈 | 활자 기호는 비기술 사용자가 해독하지 않는다 |
| 「지금 눈여겨볼 것」 우측 [AI에게 묻기] ×3 | 홈 | 같은 CTA 3개는 CTA 0개 |
| 「문의 / 미답변」 · 「리뷰 / 부정」 복합 칸 | 홈 채널별 표 | 한 칸에 숫자 둘 |
| 「답변 필요」 뱃지 (전 행 100%) | 문의 목록 | 모든 행에 있으면 정보량 0 |
| 필터 레일의 상시 노출 | 문의 | 행이 열리면 숨김, 아니면 접기 |
| "왼쪽 목록에서 항목을 고르면…" 빈 패널 | 문의 | 도착 시 화면 40%가 안내문 |
| 근거의 `locator` 문자열 | 문의 상세 | 기술 식별자 |
| 근거 목록 상시 펼침 | 문의 상세 | 요약 1줄 + 펼치기 |
| 「문의 답변 초안」 섹션 | 에이전트 | 문의 화면이 이미 소유한 워크플로의 두 번째 입구 |
| 「판매 계정 (리뷰 답변에 필요)」 select 상시 노출 | 에이전트 | 대부분의 질문에 불필요 |
| 채널 카드의 「자동 수집 지원: …」 pill | 채널 연결 | capability 언어 |

## 6. Redesign — 정보 위계

### 홈 (`/`) — 영역 2개, 그 아래 참고

```
운영 현황                                   [최근 7일 14일 30일]
─────────────────────────────────────────────────────
① 오늘 상태          주문 169건   미답변 문의 26건   확인할 리뷰 0건
   (숫자 3개, 34px)   ← 가장 큰 활자. 나머지는 이 아래로
   매출 250만원 · 문의 2건 · 리뷰 36건        ← 보조 한 줄
─────────────────────────────────────────────────────
② AI가 먼저 확인한 일 1건
   ┌───────────────────────────────────────────┐
   │ [답변 준비됨]  카페24 자사몰               │
   │ 안녕하세요. 연동 테스트 중입니다…          │  [확인하기]
   │ 답변 초안을 준비했습니다.                  │
   └───────────────────────────────────────────┘
─────────────────────────────────────────────────────
지금 눈여겨볼 것 / 추이 / 채널별 / 이 숫자에 대하여   ← 참고
```

### 문의 (`/inquiries`) — 행이 열리면 화면이 바뀐다

```
[행 미선택]  필터(접힘 요약) │ 목록 ─────────────────────
[행 선택됨]  목록(320px)     │ 고객 문의 + AI 답변 (나머지 전부)
```
목록은 자체 스크롤을 갖는다(현재는 페이지 전체가 11,580px).

### 문의 상세 — A→B→C→D

```
A  고객 문의                       ← 가장 큰 글자
   "안녕하세요. 연동 테스트 중입니다…"
   카페24 자사몰 · 2시간째        [상품 지정]

B  AI 답변                         ← 두 번째로 큰 글자
   문의 확인 안내
   안녕하세요. 보내주신 …

   ▸ AI가 확인한 내용 (상품 정보 2개 · 과거 답변 1개)   ← 기본 접힘
   ! 배송 기준이 등록되어 있지 않습니다                 ← 할 일로 표기

C  [초안 복사]  ← 하나의 primary
   수정 · 다시 작성                ← 텍스트 수준 보조
   복사해서 카페24 판매자센터에 등록하면 끝납니다.
```

## 8. 무엇을 바꿨나 — 화면별

### 8.1 홈 (`Overview.tsx` · `Metric.tsx` · `InsightList.tsx`)

| before | after |
|---|---|
| KPI 카드 6개, 크기 동일 | **주문 · 미답변 문의 · 부정 리뷰** 3개(`text-4xl`) + 매출·문의·리뷰 한 줄 |
| `AI가 먼저 확인한 일 1건` 한 줄 배너 | **카드 그대로** — 뱃지 / 고객이 쓴 문장 / 왜 / [확인하기] |
| `†` + 범례 문장 1줄 | 해당 카드에 **「최신 수집 확인 안 됨」** 네 단어 |
| 「지금 눈여겨볼 것」 행마다 [AI에게 묻기] ×3 | 행 전체가 링크, 반복 CTA 제거 (`agentGoal`은 모델에 그대로 있고 헤더에서 도달) |
| severity 점 = 색만 | 점 + `sr-only` 「확인 필요/지켜보기/참고」 |

`ProactiveSummaryBanner.tsx` **삭제** — 홈이 카드를 직접 들면서 존재 이유가 사라졌다.

### 8.2 문의 (`CustomerInbox.tsx` · `InboxList.tsx`)

**레이아웃이 두 가지 모양을 갖는다.** 행 미선택 → 목록이 화면 전체. 행 선택 → `[목록 340px | 상세
나머지]`. 필터 레일(11개 chip)은 접힌 `<details>`가 되고, 닫혀 있을 때 비기본값만 요약해 보여준다.
「왼쪽 목록에서 항목을 고르면…」 빈 패널은 **삭제**(도착 시 화면 40%였다).

목록의 **목록 열은 자체 스크롤**을 갖는다 — `/inquiries/{id}` 문서 높이가 **11,580px → 1,215px**
(1440×900 실측, 9.5배).

행 구조: 고객이 쓴 문장이 **첫 요소**가 되고, 유형·상태·채널·별점·시각은 그 아래 한 줄로. 「답변
필요」는 알약에서 **단어**로 — 단어는 남긴다(없앴다면 「답변함」이 색의 부재로만 구별되고, 색을 못
보는 사람에게는 아무 의미가 없다). 상품명은 행에서 **뺐다**(서버가 null 대신 「상품 미지정」을 보내고
이 org 백로그는 대부분 미연결이라 매 행에 같은 비-사실이 찍혔다).

### 8.3 문의 상세 (`InquiryResponsePanel.tsx` · `InboxDetail.tsx`) — 대표 화면

- **A 고객 문의**: 라벨은 내려가고(`text-sm text-muted`) 고객의 문장이 올라온다(`text-lg`).
- **B AI가 준비한 답변**: 초안 본문 `text-lg`, 흰 카드 안에.
- **부족한 것**: `knowledgeNote`가 회색 각주에서 **왼쪽 굵은 선 + 배경**의 할 일 줄로. 이 문장은 이
  제품의 가장 좋은 성질(모르는 것을 말한다)인데 다른 모든 각주와 같은 회색이었다.
- **C 근거**: `<details>` **기본 접힘**, 요약은 「AI가 확인한 내용 · 상품 정보 1개」. `locator`
  (`product-knowledge/USAGE:데모 운영자`)는 **화면에서 완전히 제거** — chunk id로 행동하는 판매자는
  없다.
- **D 행동**: primary 하나가 자기 줄을 갖고, 수정·다시 작성은 그 아래 ghost. 「이 환경에서는 …
  [초안 복사]로 옮겨 …」는 화면에서 가장 작은 글자였는데 **유일한 지시문**이었다 → `text-base`.
- 자동 분류(chip 3 + 요약 + 면책 4줄)도 접힘.

**되돌린 것 하나 — 「상품 미지정」.** 없애고 [상품 지정] 버튼만 남기는 쪽이 깔끔했지만, 상품 부재는
초안이 근거를 못 가진 **이유**이고 그 사실을 설명하는 gap 줄은 초안을 만들기 전에는 존재하지 않는다.
정직함이 이겨서 유지했다(`InquiryResponsePanel.draft.test.tsx`가 이 성질을 잠근다).

### 8.4 에이전트 (`Agent.tsx`)

설명문 1줄로 축소. 「문의 답변 초안」 **섹션 삭제** — 같은 화면에 `btn-primary` 두 개를 든 두 번째
워크플로였다. `prepareDraft`는 그대로이고 프롬프트 아래 보조 버튼에서 실행된다. 「외부 발송 없음」
보증은 그 버튼에 붙여 유지. 「판매 계정 (리뷰 답변에 필요)」 select는 접힘. 예시 질문은 입력 상자
**바로 아래**로(계정 선택 밑이 아니라). [실행] → **[물어보기]**.

### 8.5 리뷰 · 상품 · 채널 연결

- 리뷰: 페이지 설명 2줄 → 1줄, 채널 설명 문단 + chip 3개 → **한 줄**. 「누가 답변을 쓰는가」는
  capability 사실이라 짧은 절로 **유지**했다. 상세 패널은 리뷰를 고르기 전에는 **렌더하지 않는다**.
- 채널 연결: 「자동 수집 지원: 문의·주문」류 support chip은 **미연결 행에서만**. 연결된 채널에 대해
  그건 이미 내린 결정에 대한 설명이다. `channelSupport.ts`의 표현 규칙은 **무변경**.
- 상품: 이번 패키지에서 구조 변경 없음(§13 우선순위 5, 아래 남은 항목 참조).

### 8.6 채널 온보딩 문구 (`cafe24Tutorial/state.ts`)

## 12. 남은 P0/P1

1. **합성 행이 `data_origin='REAL'`로 저장돼 있다** (P1, 이월). 리뷰 「(합성 데이터)」 44건, 상품
   「(합성 샘플)」 8건. 데모 화면에 실제 고객 리뷰와 섞여 보인다. 고치려면 저장된 provenance를
   바꿔야 해서 historical cleanup 금지에 걸린다 — **product-owner 결정 필요**.
2. **상품 화면이 §5의 질문에 답하지 않는다** (P1). 「이 상품에서 어떤 문제가 반복되나」를 답하려면
   상품별 문의·리뷰 집계가 필요하고 그건 **새 metric**이라 §12 금지. 지금은 상품명·상품코드 두 칸이
   같은 값을 반복하는 표다. 상품명이 `15223228019`인 행도 그대로 — 정렬·표기 모두 product-owner 결정.
3. **`knowledgeNote`·`reasonNote` 문장이 길다** (P2). 「이 문의는 상품과 연결되지 않았고, 운영
   정책·과거 답변에도 해당 내용이 없어 문의 내용만 보고 쓴 초안입니다」는 backend 문자열이고 이번
   패키지는 frontend 전용이다. 표시 위계만 고쳤다.
4. **연결 전 첫 화면은 이 org에서 여전히 관찰 불가** (이월). 세 채널이 모두 연결돼 있어 튜토리얼
   진입은 코드 경로로만 확인했다. §11이 요구한 온보딩 **기능** 증명에는 미연결 org가 필요하다.
5. 상단 우측 「연결 확인 3」 알림 pill과 `/connect` 상단 배너가 같은 사실을 두 번 말한다 (P2).
