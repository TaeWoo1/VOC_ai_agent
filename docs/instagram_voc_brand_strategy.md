# 리뷰를 운영 자산으로 바꾸는 B2B VOC 분석 브랜드 전략
*(Instagram + Cardnews 채널 운영 — v0.1)*

> **Thesis**:
> **리뷰는 쌓아두는 후기가 아니라, 매주 관리해야 하는 운영 자산이다.**
> 우리는 이 한 줄을 시장에 학습시키고, 그 카테고리의 분석 신뢰 자산이
> 되는 것을 목표로 한다.
>
> **Status**: v0.1 strategy draft (2026-05-06). 본 문서는 코드 변경 없이
> 콘텐츠/포지셔닝 결정만 정리한다. 구현 항목은 §10 체크리스트 참조.
> v0.1 결정 잠금은 문서 말미 "Decision locked for v0.1" 박스 참조.
>
> **Audience**: 인디뷰티 브랜드 운영자, 브랜드 마케팅·상세페이지·CS·
> 제품팀 의사결정자. 일반 소비자가 아니다.
>
> **One-liner**:
> *“리뷰는 평점이 아니라, 브랜드의 다음 액션을 알려주는 고객 언어입니다.
> 우리는 그 고객 언어를 제품·상세페이지·CS 액션으로 번역합니다.”*

---

## 1. Positioning

### 계정 정의

```
인디뷰티 리뷰/VOC 분석 노트
리뷰를 제품·상세페이지·CS 액션으로 번역합니다
샘플 리포트 / 월간 리뷰 자산 관리 문의 DM
```

### 무엇이 아닌가 (negative definition)

- **소비자 대상 제품 추천 페이지가 아니다.** "이번 달 추천템", "인생 쿠션
  TOP 5" 같은 큐레이션 콘텐츠를 만들지 않는다.
- **리뷰 캡처 모음/짤 계정이 아니다.** 특정 제품의 리뷰 스크린샷을 모아
  보여주는 채널이 아니다.
- **브랜드 평가/순위 매체가 아니다.** "OO 브랜드 부정 리뷰 분석" 같은
  포지션은 신뢰 자산을 갉아먹는다.
- **데이터 스크래핑 도구 마케팅 채널이 아니다.** 기술/플랫폼이 아니라
  분석 결과의 운영 가치가 메시지의 중심이다.

### 무엇인가 (positive definition)

- **B2B 신뢰 구축 채널이다.** Instagram은 잠재 고객(인디뷰티 브랜드
  운영자)이 우리의 분석 관점·언어·결과물 품질을 미리 검증하는 윈도우다.
- **샘플 리포트/유료 서비스 진입 funnel의 top이다.** 게시물 → DM 문의 →
  콜드 이메일 + 비공개 샘플 리포트 → 월간 운영 계약.
- **'리뷰 운영' 카테고리 자체를 만드는 educational 매체다.** 기존에는
  "리뷰는 후기/마케팅 콘텐츠"였지만, 우리는 "리뷰는 매주 관리해야 할
  운영 자산"이라는 카테고리를 시장에 학습시킨다.

## 2. Core thesis

리뷰에 대한 기존 인식과 우리 인식의 차이:

| 기존 인식 | 우리 인식 |
|---|---|
| 별점·후기 (소비자 의사결정 보조) | 운영 결과가 쌓인 데이터 |
| 마케팅팀이 모아두는 인용구 | 제품·상세페이지·CS 팀의 공통 운영 자료 |
| 좋은 리뷰=칭찬 / 나쁜 리뷰=문제 | 좋은 리뷰=재구매·확산 신호 / 혼합 리뷰=상세페이지·옵션·기대치 미스매치 신호 / 나쁜 리뷰=내부 확인 우선순위 신호 |
| "5점이 몇 %인가" | "어떤 고객 언어가 반복되고 있는가" |
| 단발성 보고 | 매주/월간 운영 자산 관리 |

### 우리가 하지 않는 것

- 우리는 "리뷰를 요약"하지 않는다. 요약은 누구나 한다.
- 우리는 "긍·부정 비율"만 보여주지 않는다. 그건 의사결정으로 이어지지 않는다.
- 우리는 "원인을 단정"하지 않는다. 우리가 보는 것은 외부 신호이고, 원인은
  브랜드 내부 데이터(QA, 제조, CS 로그)와 합쳐야만 알 수 있다.

### 우리가 하는 것

- **반복되는 고객 언어 → 내부 운영 질문으로 번역.**
  - 예: "색이 달라요" 7회 반복 → "최근 3개월 옵션별 발색 검수 로트 변경
    여부 확인 후보"
- **신호의 우선순위화.** 빈도·증거 강도·confidence를 곱해 "지금 다음 한
  주에 무엇을 봐야 하는지"를 정한다.
- **부서 간 공통 언어 제공.** 같은 신호가 제품·상세페이지·CS·마케팅·재구매
  관점에서 각각 어떤 액션 후보를 만들어내는지 매핑한다.
- **리포트의 신뢰도 표시.** 모든 신호에 confidence axis(샘플 수, 정렬
  커버리지, 견본 인용 품질)를 노출해, 약한 신호와 강한 신호를 구분 가능하게
  한다.

## 3. Channel role separation

세 개의 채널을 **명시적으로 분리**한다. 같은 분석 결과라도 채널별로 노출
범위, 식별성, 톤이 다르다.

### A. Instagram — 공개 신뢰 채널

- **목적**: B2B 잠재 고객이 우리의 관점·언어·결과물 품질을 검증하게 한다.
- **콘텐츠 범위**:
  - 방법론 (어떻게 신호를 잡고 어떻게 우선순위화하는지)
  - 해석 프레임워크 (어떤 리뷰 패턴이 어떤 운영 질문으로 이어지는지)
  - 익명/카테고리 단위 패턴 (브랜드/제품 식별 불가)
  - 리포트 구조 미리보기 (블러 처리된 섹션 구성, 가짜 데이터 기반 예시)
  - 합의된 case study (브랜드의 명시적 동의가 있는 경우만)
- **무엇이 없는가**: 식별 가능한 브랜드/제품의 부정 분석, raw 리뷰 인용,
  랭킹 매기기, 무동의 case study.

### B. Cold email / private demo — 잠재 고객 1:1 채널

- **목적**: 개별 브랜드에 "당신의 제품이라면 이런 리포트가 나옵니다"를
  보여줘 유료 전환을 만든다.
- **콘텐츠 범위**:
  - 해당 브랜드의 공개 리뷰(공개 채널의 공개 데이터)를 사용한 샘플 리포트
  - 리포트는 운영 가설 형태(`~검토 후보`, `~가능성`)로만 작성
  - DM/이메일 1:1 발송, 비공개
- **무엇이 없는가**: SNS 공개 게시, 동의 없는 외부 공유, 다른 브랜드 비교
  (단일 브랜드 단독 리포트만).

### C. Paid service — 월간 운영 채널

- **목적**: 브랜드가 직접 제공한 데이터(셀러센터, API 권한, CSV, CS 로그,
  자체 보유 데이터)를 받아 월간 단위로 VOC를 운영 자산화한다.
- **콘텐츠 범위**:
  - 브랜드 내부에서만 열람되는 리포트
  - 셀러센터 주문/CS 데이터와 결합된 confidence 강화
  - 부서 회의 아젠다 형태로 정리된 "이번 주 검토 후보" 리스트
  - 실험·검증 / 중기 개선 / 즉시 실행 카테고리별 운영 큐
- **무엇이 없는가**: 외부 공개, 다른 브랜드와의 데이터 결합, 우리 내부에서의
  부수 활용.

### 채널 간 데이터 흐름 규칙

```
공개 리뷰(scraped, 동의 불필요) ─┬─→ A. Instagram (anonymized only)
                              └─→ B. Private demo (1:1, 비공개)

브랜드 제공 데이터 ──────────────→ C. Paid service (외부 노출 없음)

C → B 흐름은 가능 (consented case study로 변환 후)
B → A 흐름은 불가 (식별성 제거 + 명시 동의 없으면)
A → B 흐름은 자연스러움 (공개 콘텐츠 보고 DM 유입)
```

### D (deferred) — B2C affiliate / 제품 추천

이 채널은 **포기한 것이 아니라, 분리해서 별도로 다룰 트랙**이다.

- **상태**: deferred. 본 v0.1 전략 범위 외.
- **가능한 미래 형태**:
  - 별도 Instagram/블로그 계정 (다른 브랜드명)
  - 또는 본 분석 인프라 위에 얹힌 별도 mini-service (예: 카테고리별
    "검토할 만한 제품" 큐레이션)
- **왜 본 B2B 채널과 같은 계정에서 못 하는가**:
  - **이해 상충**. 추천/affiliate 인센티브가 있는 매체는 "어떤 브랜드의
    리뷰를 어떻게 분석했는가"의 객관성에 의심을 만든다. 우리가 브랜드 측
    데이터 신뢰 자산을 팔면서 동시에 소비자 측 추천 commission을 받는다면,
    브랜드 입장에서는 "이 분석가는 왜 우리 데이터를 보고 있는가"라는
    합리적 의심을 한다.
  - **톤 충돌**. B2B는 "단정하지 않는 분석가" 톤이고, B2C 추천은 "이 제품
    좋다/추천한다" 단정 톤이다. 한 계정에서 같이 하면 둘 다 약해진다.
  - **타깃 충돌**. 브랜드 운영자와 일반 소비자는 같은 게시물에서 다른
    것을 본다. 둘을 한 자리에서 만족시키려 하면 둘 다 떠난다.
- **분리 원칙**:
  - 본 B2B 계정에서 절대 affiliate 링크/제품 추천을 게시하지 않는다.
  - 본 B2B 계정에서 "이 제품을 사세요/추천합니다" 톤을 사용하지 않는다.
  - B2C 트랙을 시작할 경우 별도 브랜드/계정/disclosure 정책으로 운영한다.
- **재검토 시점**: 본 B2B 채널이 안정화된 후 6개월(예: 첫 50개 게시물 +
  유료 운영 계약 N건 이후)에 별도 결정 트랙으로 재검토.

## 4. Public content principles

### 허용 (Allowed)

- **가상/재구성된 리뷰 예시.** "한 인디 쿠션 브랜드의 리뷰에서 자주 보이는
  패턴은…" 같은 익명 재구성. 실제 리뷰 텍스트가 아니라 패턴 추출 후 재진술.
- **익명화된 패턴.** "립틴트 카테고리에서 ‘색이 달라요’가 반복되는 경우의
  3가지 해석 후보".
- **카테고리 단위 인사이트.** "선크림 리뷰에서 백탁 vs 발림성 trade-off가
  어떻게 분포되는지".
- **리뷰 해석 프레임워크.** "혼합 리뷰가 긍정 리뷰보다 상세페이지 카피에
  더 유용한 이유" 같은 방법론.
- **리포트 구조 미리보기.** 가짜 데이터로 채운 리포트 페이지의 구성/섹션
  미리보기. 실제 브랜드 데이터 아님을 명시.
- **합의된 case study.** 브랜드의 명시적 서면 동의가 있는 경우에 한해
  실제 사례 공개. 브랜드 노출 범위/표현 수위/표시 기간을 동의서에 명시.
- **짧은 재구성 예시 문장.** "‘좋긴 한데요…’가 뒤에 무엇이 붙느냐가
  실제 신호" 같은 어구 인용은 가상 문장으로.

### 제한/금지 (Restricted / prohibited)

- **무동의 브랜드별 부정 분석.** "OO 브랜드 부정 리뷰 분석"류 포스팅 금지.
  브랜드 평판 침해 + 신뢰 자산 훼손.
- **"OO 브랜드 리뷰 분석 결과" 형식.** 동의 없는 단일 브랜드 식별 콘텐츠
  전반 금지.
- **제품 단위 공개 비판.** "이 제품은 이런 문제가 있습니다" 같은 단정형
  제품 평가 금지.
- **대량 리뷰 인용.** 한 번의 게시물에 raw 리뷰 텍스트 다수 인용 금지.
  소비자 측 저작권/플랫폼 ToS + 브랜드 측 신뢰 모두 위험.
- **raw scraped data 노출.** 스크래핑한 원천 데이터(JSON, CSV, 캡처) 공개
  금지.
- **부정 리뷰로 브랜드 랭킹.** "부정 리뷰 많은 인디뷰티 BEST/WORST 5"류
  콘텐츠 금지.
- **affiliate-style 추천(미공시).** 공시 없는 제품 추천 또는 협찬 추천 금지.
  광고/제휴 표시 의무 준수.
- **플랫폼/스크래핑 중심 포지션.** "셀러를 위한 리뷰 스크래퍼" 같은 도구
  마케팅 금지. 우리는 결과의 운영 가치를 판다.

### 검증 메커니즘 (운영 규칙)

- 모든 공개 cardnews는 게시 전 **2-eye review**: 작성자 1명 + 검토자 1명.
- 검토 체크리스트:
  - [ ] 식별 가능한 브랜드명/제품명/이미지가 있는가? (있으면 동의서 첨부 확인)
  - [ ] raw 리뷰 인용이 있는가? (있으면 가상 재구성으로 교체)
  - [ ] 단정형 표현이 있는가? ("필요/해야 함/원인은" → 후보형으로 교체)
  - [ ] 의학적 효능 단정이 있는가? (있으면 즉시 제거)
  - [ ] confidence/방법론 안내가 본문 또는 링크에 노출되어 있는가?
- 후속 자동화는 §10 체크리스트의 `safety_validator(public_education_mode)`에
  encode.

## 5. Tone of voice

### 정의

> **"단정하지 않지만, 실무적으로 유용한 분석가."**

분석가는 데이터의 한계를 안다. 그래서 단정하지 않는다. 동시에 "그래서
다음 한 주에 무엇을 볼 것인가"라는 질문에 답을 가지고 있다. 그 두 톤이
한 문장에 같이 있어야 한다.

### Tone 예시 (Korean voice samples)

- "이 신호만으로 제품 문제라고 단정할 수는 없습니다."
- "다만 반복된다면 내부 확인 질문으로 바꿔볼 수 있습니다."
- "리뷰 분석의 목적은 범인을 찾는 것이 아니라, 검토 우선순위를 정하는
  것입니다."
- "리뷰는 쌓아두는 후기가 아니라 매주 관리해야 하는 운영 자산입니다."
- "‘좋긴 한데요’ 뒤에 어떤 단어가 붙는지가 실제 신호일 수 있습니다."
- "부정 리뷰가 적다고 안전한 것은 아닙니다 — 보이지 않는 이탈도 같이
  봐야 합니다."
- "리뷰는 회의에서 인용되는 자료가 아니라, 회의의 아젠다가 될 때 운영
  자산이 됩니다."

### Tone 회피 표현 (do-not list)

- "혁신적", "최첨단", "AI 기반의" — 도구 마케팅 톤. 우리 가치는 결과의
  유용성에 있지 기술 자랑에 있지 않다.
- "꼭 ~해야 합니다", "~이 정답입니다" — 단정형. 우리가 보는 것은 외부 신호
  뿐이고, 원인은 내부 데이터와 결합해야 안다.
- "OO 브랜드처럼 실패하지 않으려면" — 비교/공포 마케팅. 신뢰 자산 훼손.
- "쉽게/간단하게" — 분석의 깊이를 가볍게 만드는 표현.
- "후기 분석" — "후기"는 소비자 언어. 우리는 "VOC", "리뷰 운영 자산",
  "고객 언어"로 다룬다.

## 6. Content pillars

5개 pillar로 분기한다. 모든 게시물은 정확히 1개 pillar에 속한다.

### Pillar 1 — 리뷰 해석 노트

- **Purpose**: "이런 리뷰 표현은 어떤 신호로 해석할 수 있는가"를
  교육한다. 분석가의 시선을 공개한다.
- **Example topics**:
  - "‘색이 달라요’의 4가지 해석 가능성"
  - "‘건조해요’ 리뷰가 피부 타입에 따라 다르게 읽혀야 하는 이유"
  - "‘좋긴 한데요’ 뒤에 붙는 단어가 진짜 신호"
- **Card flow** (8장):
  1. 표현 인용 (가상 재구성)
  2. 표면 해석 / 일반적 인식
  3. 그 해석의 한계
  4. 다른 해석 후보 1
  5. 다른 해석 후보 2
  6. 다른 해석 후보 3
  7. 어떻게 우선순위 정할 것인가
  8. 샘플 리포트 CTA

### Pillar 2 — 리뷰 → 내부 확인 질문

- **Purpose**: 리뷰 신호를 운영팀이 들고 가서 쓸 수 있는 "확인 질문"으로
  변환하는 방법을 보여준다. Pillar 1보다 한 단계 더 실무적.
- **Example topics**:
  - "‘펌프가 자꾸 막혀요’ → OEM에 무엇을 물을 것인가"
  - "‘색이 달라요’ → 옵션 발색 검수 변경 이력 확인 질문 만드는 법"
  - "‘향이 너무 진해요’ → 향료 로트 vs 표현 미스매치 어떻게 구분"
- **Card flow** (7장):
  1. 반복되는 고객 언어 (가상)
  2. 빈도/맥락 요약
  3. 가능한 내부 원인 후보 3개
  4. 내부 확인 질문 후보 1 (제품/제조)
  5. 내부 확인 질문 후보 2 (상세페이지/기대치)
  6. 내부 확인 질문 후보 3 (CS 응대)
  7. CTA

### Pillar 3 — 상세페이지 개선 신호

- **Purpose**: 리뷰가 상세페이지(LP)의 어떤 부분이 부족한지 알려주는
  방식을 보여준다. 마케팅·상세페이지 운영자 후킹.
- **Example topics**:
  - "혼합 리뷰가 긍정 리뷰보다 LP 카피에 더 유용한 이유"
  - "리뷰에서 LP FAQ 항목 뽑는 법"
  - "‘기대했던 것과 달라요’가 LP의 어느 섹션을 다시 보라는 신호인지"
- **Card flow** (7장):
  1. 리뷰 패턴 (가상)
  2. LP에 명시되어 있어야 할 정보가 빠진 사례
  3. 리뷰 표현 → LP 카피 reverse-engineering 예시
  4. FAQ 후보 도출
  5. 옵션/베리언트 설명 보강 후보
  6. 검토 우선순위 기준
  7. CTA

### Pillar 4 — 월간 VOC 운영법

- **Purpose**: "리뷰는 매주/매월 관리해야 하는 운영 자산"이라는 카테고리
  자체를 학습시킨다. 가장 추상적·교육적 pillar.
- **Example topics**:

  - "리뷰를 제품/마케팅/CS팀이 같이 보는 법"
- **Card flow** (8장):
  1. 문제 제기 (왜 매주 봐야 하는가)
  2. 일반적으로 안 보는 지표
  3. 봐야 할 지표 1
  4. 봐야 할 지표 2
  5. 봐야 할 지표 3
  6. 운영 회의로 끌어오는 방법
  7. 신뢰도 표시의 중요성
  8. CTA

### Pillar 5 — 익명/가상 운영 사례

- **Purpose**: "이런 브랜드의 이런 상황에서 우리는 이렇게 본다"를 가상

- **Example topics**:
  - "한 인디 쿠션 브랜드의 ‘색이 달라요’ 누적 패턴 — 가상 사례"
  - "한 패드 브랜드의 ‘건조해요’ 분포 — 피부 타입별 가상 분석"
  - "재구매율은 높은데 신규 후기는 ‘기대 이하’가 늘어나는 가상 케이스"
- **Card flow** (10장):
  1. 가상 브랜드/제품 설정 (명시적으로 "가상 사례" 표시)

  4. 우리가 본 신호 1
  5. 우리가 본 신호 2
  6. 우리가 본 신호 3
  7. 내부 확인 질문 후보
  8. LP 보완 후보

  10. CTA + "실제 브랜드 데이터로 보고 싶으면 DM"

## 9. Cardnews mode implications

향후 cardnews 시스템이 지원해야 할 3가지 mode를 정의한다.

### Mode 분류

| Mode | 노출 범위 | 식별성 | 데이터 출처 |
|---|---|---|---|
| `private_demo` | 1:1 (DM/email) | 식별 가능 | 공개 리뷰 (scraped) |
| `public_education` | 공개 (Instagram) | 비식별 (가상/익명) | 가상 재구성 또는 카테고리 집계 |
| `consented_case_study` | 공개 (Instagram) | 식별 가능 (동의 명시) | 공개 리뷰 + 명시 동의 |

### 현재 시스템 상태와 mode 매핑

- **현재 cardnews/ 출력은 default `private_demo`로 간주한다.**
  - 브랜드명/제품명 명시, 평점·리뷰 수 등 raw metrics 노출, "한 줄 인용"
    단위로 raw text 사용 가능 — 이 모든 것이 **공개 콘텐츠 원칙(§4)을
    위반**한다. 따라서 그대로 SNS 공개 금지.
  - private demo 채널(B)에서 1:1 비공개로만 사용한다.

### `public_education` planner — 별도 설계 필요

다음 항목이 cardnews planner에 추가되어야 한다 (구현은 §10에서 단계별로):

1. **Brand-level 익명화 layer**:
   - 브랜드명/제품명/SKU 코드를 게시물 surface에서 제거.
   - 카테고리만 남김 (예: "한 립틴트", "한 쿠션 베이스").
   - 이미지 사용 금지 또는 silhouette/illustration으로 대체.
2. **Raw quote 금지**:
   - `analysis_report.json`의 `quote` 필드 직접 노출 금지.
   - 대신 quote의 패턴만 추출해 가상 재구성 (`"색이 달라요" 같은 표현이
     반복되는 경우`) 형태로.
3. **Confidence/sample-size 표시 강제**:
   - 모든 신호 카드에 "이 패턴은 약 N건의 익명 리뷰에서 관찰됨" 또는
     "category-level 패턴" 같은 약식 confidence 표기.
4. **CTA fixed**: "샘플 리포트 / 월간 운영 문의는 DM" 형태 통일.
5. **Safety validator 확장**:
   - 기존 `cardnews.safety_validator.BANNED_FRAMINGS_KO`를 베이스로,
     `public_education_mode`에서만 활성화되는 추가 ban list:
     - 브랜드/제품 식별 가능한 표현
     - "발색", "지속력" 같은 attribute label에 직접 매핑된 brand-specific
       quote
     - 평점/N% 같은 raw metric 텍스트
6. **Template 분리**:
   - `cardnews/templates/public_education/*.html.j2` 신설.
   - 기존 `templates/seller_demo/*` (사실상 현재 템플릿)와 디렉토리 분리.

### `consented_case_study` planner — v2 이후

- 동의서 양식 정의 (브랜드 식별 범위, 표시 기간, 회수 조건).
- 동의서 ID를 cardnews manifest에 기록.
- 게시물 surface에 "본 사례는 OO 브랜드의 명시적 동의 하에 공유되었습니다"
  disclosure 강제.
- 단일 브랜드만 노출 (비교/랭킹 금지).

### 단기 운영 결정

> **현재 단계(첫 20개 공개 게시물)에서는 cardnews 자동 생성을 사용하지
> 않는다.** 모든 공개 게시물은 수동 작성·수동 검토·수동 게시한다. 자동화는
> public_education planner가 §10 체크리스트대로 구현된 이후에 enable.

## Decision locked for v0.1

> 다음 결정들은 v0.1에서 잠긴다. 변경하려면 본 문서의 명시적 revision이
> 선행되어야 하며, 한 게시물·한 commit 단위로 우회하지 않는다.

- **Instagram = B2B 신뢰 채널.**
  인디뷰티 브랜드 운영자(제품/LP/CS/마케팅 의사결정자)를 대상으로 한 신뢰
  구축 채널. 일반 소비자 대상 추천/큐레이션 채널이 아니다.

- **현재 product-specific cardnews = `private_demo` mode.**
  현재 `cardnews/render.py`가 만들어내는, 브랜드명·제품명·평점·raw quote가
  포함된 산출물은 모두 `private_demo`로 분류된다. SNS 공개 불가. 1:1
  비공개 채널(DM/email)에서만 사용한다.

- **공개 Instagram = `public_education` mode, 익명/카테고리 단위, 초기 수동.**
  Instagram에 올라가는 모든 게시물은 `public_education` mode이며, 브랜드/
  제품 식별성이 제거된 익명 또는 카테고리 단위 콘텐츠에 한한다. 첫 20개
  게시물은 수동 작성하며, 자동화는 tone/safety/CTA 검증 이후에만 enable.

- **B2C affiliate / 추천 = deferred separate experiment.**
  본 B2B 채널과 동일 계정에서 절대 운영하지 않는다. 미래에 별도 브랜드/
  계정/disclosure 정책으로 분리될 수 있는 별개 트랙. 본 B2B 채널이 안정화된
  후 6개월 시점에 별도 결정 트랙으로 재검토.
