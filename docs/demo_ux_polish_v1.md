# Demo UX Polish v1 — 화면 감사와 정리

**날짜:** 2026-08-26 · **범위:** `frontend/` 전용 (backend·collector·agent-runtime·contracts 무변경)
**성격:** 기능 추가 없음. 이미 있는 기능을 **덜 복잡하게 · 더 읽기 쉽게 · 더 행동하기 쉽게** 만든다.

목표는 「예쁜 화면」이 아니라, 처음 본 판매자가 **지금 무슨 상황인지 · AI가 무엇을 해뒀는지 ·
자기가 무엇을 해야 하는지**를 첫 화면에서 이해하는 것이다.

---

## 1. 어떻게 감사했나

로컬 스택(backend 8080 · frontend 5173 · agent-runtime 8787)에 실제 Demo Org
(`7146c50f-…`, 실데이터 — `inquiries` 3,476 · `reviews` 4,565 · `products` 320)로 로그인해 **1440×900 데스크톱**에서
16개 경로를 실제 렌더 기준으로 관찰했다. 화면마다 렌더 텍스트 전문, 스크린샷, 문서/스크롤 높이,
가로 오버플로, 콘솔 오류를 남겼다. 마켓플레이스 호출 0 · DB 변경 0 — 읽기와 화면 캡처만 했다.

관찰한 경로: 홈 · 상품 목록 · 상품 상세 · 리뷰 · 문의 · 문의 상세(프로액티브 카드가 가리키는 그 문의)
· 주문 · 고객운영 메모리 · 리포트 · 에이전트 · 채널 연결 · 카페24 튜토리얼 · NAVER 연결 · 쿠팡 연결 ·
설정 · 운영 정책.

## 3. 정보 구조 — 무엇을 무엇의 위에 두는가

화면 역할은 그대로다(홈=상황 인지 · 문의=오늘 처리할 일 · 문의 상세=판단과 답변 · 상품=상품 운영
기억 · 에이전트=복합 조사). 바뀐 것은 **한 화면 안의 순서와 폭**이다.

- **문의 상세는 가장 좁은 칸이 아니라 가장 넓은 칸이다.** `200px / 1fr / 400px` → `168px / 0.85fr /
  1.15fr`. 질문·근거·초안이 같이 읽혀야 하는 칸이 필터 레일보다 좁을 이유가 없다.
- **프로액티브 섹션은 행이 열려 있으면 렌더하지 않는다.** 그 섹션의 일은 「무엇부터 볼까」에
  답하는 것이고, 스스로의 [확인하기]를 따라온 판매자는 이미 그 답 안에 있다.
- **고객의 말이 행이다.** 행 제목은 고객이 쓴 문장이고 상품명은 메타데이터 줄로 내려갔다.
- **분류는 일 다음이다.** 「자동 분류」 칩 한 줄이 고객 문의·AI 답변 아래로 갔다 — 힌트가 일보다
  위에 있을 이유가 없다.

## 4. 실제 수정 (frontend 전용)

**새로 만든 것 2개.**

- `lib/plainText.ts` — 채널이 보낸 마크업을 **표시 단계에서만** 벗긴다. 태그는 해석하지 않고
  제거하며(`innerHTML` 미사용), 저장된 행은 건드리지 않는다. 승인된 초안이 무엇과 대조됐는지는
  그대로다. 엔티티는 실제로 등장하는 것 + 구조적인 넷만 디코딩하고, 모르는 엔티티는 **추측하지
  않고 그대로 둔다**.
- `lib/productVocabulary.ts` — `SellingStatus`가 **자기 매핑 표에 적어 둔 한국어 원단어**를 되돌려
  준다(`판매중` / `판매중지·품절` / `판매종료` / `상태 미상`). 지어낸 단어가 아니다.
  `products.status`는 **한국어 이름을 주지 않고 화면에서 뺐다** — 카탈로그 writer가 리터럴
  `"ACTIVE"` 하나만 쓰는 자유 문자열이라, 구분할 두 번째 값이 없는 칸이었다.

## 5. 디자인 규칙 — 새 프레임워크 없음

기존 토큰과 컴포넌트만 썼다(`brand`/`brand-50`/`brand-700`, `line`, `canvas`, `surface`, `ink`,
`muted`, `Btn`/`BtnLink`, `Chip`, `SectionHeader`, `PageHead`). 새 색 단계·새 spacing scale·새
컴포넌트 라이브러리 **0**. 정리한 규칙은 셋뿐이다.

1. **한 화면의 primary는 하나다.** 프로액티브 CTA가 solid이면 같은 블록의 다른 컨트롤은 ghost다.
2. **설명은 정보를 담을 때만 남는다.** 매 방문 같은 문장을 반복하는 hint는 삭제하거나 숫자로 바꾼다.
3. **같은 사실을 두 번 말하지 않는다.** 정의는 참조 블록이, 상태는 렌더가, 근거는 근거 목록이 소유한다.

## 6. 브라우저 QA

수정 후 대표 흐름을 실제로 따라갔다: 홈 → 프로액티브 배너 → 문의 → 카드 [확인하기] → 문의 상세
→ 초안 → 상품 → 에이전트 → 채널 연결.

- 16개 경로 × **1440×900**과 **390×844**: 문서 가로 오버플로 **0**, 콘솔 오류 **0**.
  (리뷰 화면의 `<li>` 중첩 경고는 §2-10 수정으로 사라졌다.)
- 마크업 잔존 확인: 문의·리뷰 렌더 텍스트에서 `<meta` / `&ldquo;` / `&amp;` / `&#` **0건**.

## 7. 고치지 않은 것 — 그리고 왜

**A. UX가 아니라 데이터인 것 (이번 패키지 밖)**

1. **합성 행이 `data_origin='REAL'`로 저장돼 있다.** 리뷰 목록에 「(합성 데이터)」 44건, 상품에
   「(합성 샘플)」 8건이 실제 고객 리뷰와 섞여 보인다. `realDataOnly` 필터가 있는데도 걸러지지
   않는 이유는 그 행들이 스스로를 REAL이라고 말하기 때문이다. 고치려면 저장된 행의 provenance를
   바꿔야 하고, 이번 패키지는 **historical cleanup을 하지 않는다**. 데모에서 보이므로 우선순위는
   높다.
2. **상품 목록 상단이 숫자 이름이다** (`170`, `91`, `15223228019`). 이름이 채워지지 않은 카탈로그
   행이 알파벳 정렬에서 먼저 온다. 정렬을 신호 기준으로 바꾸는 것은 화면 규칙 변경이 아니라
   **새 랭킹**이라 product-owner 결정 사항으로 보고한다.
3. **`(미지정 상품)` 버킷 행이 상품 목록에 상품처럼 보인다.**

**B. 커넥터 상태/오케스트레이션 (별도 목록, 이번에 착수하지 않음)**

4. **연결 전 첫 화면을 이 org에서는 관찰할 수 없었다.** Demo Org는 세 채널이 모두 연결돼 있어
   모든 채널 행이 [연결 관리]로 렌더된다. 코드 경로는 확인했다 — `ChannelList.handleAction`이
   `connect-cafe24` → `/connect/cafe24/tutorial`, `connect-naver` → `/connect/naver`,
   `connect-coupang` → `/connect/coupang`로 보내므로 **7단계 카페24 튜토리얼은 미연결 상태에서
   실제로 진입점을 갖는다**. 다만 「튜토리얼식 안내가 제대로 작동하지 않는다」는 보고를 이 org에서
   **재현하지 못했다**. 재현에는 채널이 붙지 않은 org가 필요하고, 그것을 만드는 것은 DB에 org를
   추가하는 일이라 하지 않았다.
5. 카페24 튜토리얼 2단계 이후는 **실제 mall ID가 있어야** 진행된다. 문구만 감사했고 단계 전이·성공/
   실패 표현은 미관찰.
6. 카페24 튜토리얼에 **[이전] 컨트롤이 없다**(스텝퍼는 상태 표시 전용).

**C. 남은 P1/P2 (화면)**

7. 리뷰 화면은 목록 위에 필터 칩이 3묶음(채널 탭 · 정렬 · tier) 쌓인다. 이번에 손대지 않았다 —
   축소하려면 어떤 축을 접을지 결정이 필요하고, 그건 리뷰 워크플로 결정이다.
8. 홈 「지금 눈여겨볼 것」의 행마다 붙는 [AI에게 묻기]는 그대로 뒀다. 행 자체가 primary 링크
   (`font-semibold text-ink`)이고 AI 링크는 `text-sm text-muted`라 위계는 이미 다르다.
9. 상품 상세의 「일부 신호는 이 상품에 연결되지 않아…」는 정상 상태인데 경고 톤(amber)이다.

## 8. 이 패키지가 하지 않은 것

새 Agent tool · 새 커넥터 · 새 대시보드 지표 · 워크플로 엔진 · 벡터 DB · 알림/메일/푸시 ·
