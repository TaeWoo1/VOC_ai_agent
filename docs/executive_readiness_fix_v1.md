## 1. 감사 먼저 — 숫자는 틀리지 않았다

리뷰에서 「모순」으로 지목된 셋을 backend에서 확인한 결과, **셋 다 값은 정확했고 화면이 기간을
말하지 않았을 뿐이다.**

| 화면에 보이던 것 | 실제 계산 | 기간 |
|---|---|---|
| 매출·주문·문의·리뷰·부정 리뷰 | `OperationsMetricsService` window 집계 | `from..to` (최근 N일) |
| **미답변 문의 26** | 같은 서비스의 `unansweredNow(...)` | **기간 없음 — 현재** |
| 채널표 `문의 / 미답변` = `2 / 26` | 좌=window, 우=now | **두 기간이 한 칸에** |
| 인사이트 「부정 리뷰 3건」 | `OperationsInsightsService.negativeProduct` — 상품별 전체 기록 | **전체 기간** |
| 인사이트 「반복되는 리뷰 문제 19건」 | `repeatedIssue` — 열린 이슈 전부 | **전체 기간** |

그래서 backend 숫자는 **하나도 건드리지 않았다.** 고친 것은 라벨·열·표시 층이다.

**구분은 열거하지 않고 파생한다.** point-in-time 숫자는 비교할 이전 기간이 없어 payload에
`comparable: false`로 도착한다. 접두사를 그 필드에서 읽으므로, 나중에 추가되는 KPI도 목록을
고치는 사람 없이 맞게 표시된다. 명사만 key로 덮어쓰며, 그것도 backend의 단어가 옆의 다른 단어와
붙었을 때 모호해지는 한 곳뿐이다 (`문의` → `신규 문의`).

### 결과

- `최근 7일 주문` · `현재 미답변 문의` · `최근 7일 부정 리뷰`
- 조용한 줄: `최근 7일 매출` · `최근 7일 신규 문의` · `최근 7일 리뷰`
- 채널표: `문의 / 현재 미답변` **두 열**로 분리, 섹션 힌트가 어느 열이 window이고 어느 열이 now인지 명시
- 인사이트: 전체 기간 집계 행에 `전체 기간` 표식
- **`INQUIRY_BACKLOG` 행은 홈에서 뺐다** — 바로 위 「현재 미답변 문의 26건」 카드와 같은 소스·같은
  숫자이고, 그 detail(「카페24 자사몰 26건이 가장 많습니다」)은 채널표의 새 열이 말한다. 한 화면에서
  26을 세 번 만나면 문제가 셋으로 읽힌다. 홈에서만 빠지며 문의 화면은 자기 헤더 수치로 계속 들고 있다.

## 2. 문의 상세 — fold와 primary CTA

**측정된 결함:** 1440×900에서 「초안 복사」가 **y=901**, fold는 900. 125%(720px)에서는 181px 아래.
첫 화면에서 누를 수 있는 것은 「상품 지정」(높이 **20px**) 하나뿐이었다.

**시도했다가 되돌린 것 — sticky.** 액션 블록을 pane 스크롤러 바닥에 고정했더니 CTA는 항상 보이지만
그 막대가 **199px**이라 초안 본문과 근거 안내를 덮었다. 하나의 실패를 다른 실패로 바꾼 것이라 철회했다.

**채택한 것:** 복사 컨트롤을 **초안 카드의 헤더**로 옮겼다. 블록 자신의 복사 버튼이 블록 머리에
있는 것은 관례이고, 초안이 보이는 한 버튼도 보인다 — 확대율과 본문 길이에 무관하다. 아래쪽에는
중복해 그리지 않는다. **답변을 실제로 등록할 수 있는 채널에서는 「답변 보내기」가 여전히 primary이며
확인 단계와 함께 아래에 남는다** — 제품에서 유일한 되돌릴 수 없는 컨트롤을 보낼 텍스트 옆으로
옮기지 않는다.

**함께 걷어낸 중복 chrome** (전부 한 화면 안에서 다시 말해지던 것):
- 상세 route가 목록 route의 머리말(설명 + 「지금 답변이 필요한 문의 26건」)을 그대로 쓰던 것 → 제거,
  제목은 `compact`
- 상세 패널 상단의 `문의 · 답변 필요 · 3시간 전` 줄 → 유형은 페이지 제목이고, 시각은 패널 자신의
  context 줄에 있고, 상태는 왼쪽 rail의 선택된 행에 있다
- 「고객 문의」 라벨 → `sr-only`로 남기고 화면에서 제거

### 측정 결과

| | 100% (1440×900) | 125% (1152×720) |
|---|---|---|
| 고객 질문 | 보임 | 보임 |
| 근거 없음 안내 | 보임 | 보임 |
| 초안 제목 | 보임 | 보임 |
| **primary CTA 「초안 복사」** | **보임** (y=596) | **보임** (y=623, bottom 670) |
| 초안 본문 | **전부 보임** (bot 741) | **첫 줄만** (y=676, 44px) |

**125%에서 초안 본문 전체는 여전히 스크롤이 필요하다.** 남은 chrome을 다 걷어내도 질문 5줄 +
근거 안내 3줄 + 초안 5줄은 720px에 들어가지 않는다. 정직하게 남긴다 — CTA를 발견해야 하는 문제는
닫혔고, 본문을 읽는 스크롤은 본문이 길기 때문이다.

## 3. 접근성 — 실측으로 AA green

전 화면의 **모든 보이는 텍스트 노드**를 합성된 실제 배경과 대조해 측정했다 (`scratchpad/contrast.mjs`).

| 항목 | 전 | 후 |
|---|---|---|
| `.btn-primary` 흰 글자 (58곳 — Agent 주 CTA, 온보딩·튜토리얼 전부) | `bg-brand` **3.71:1** | `bg-brand-700` **5.41:1** |
| `warn` 토큰 — 「확인 필요」 칩·「연결 문제」 (자기 tint 위) | `#B45309` **4.39:1** | `#92400E` **6.20:1** |
| `good` 토큰 — 「연결됨」·「최신」·「외부 발송 없음」 | `#15803D` **4.00:1** | `#12662F` **5.55:1** |
| VOC 복사 버튼 | `bg-brand` 3.71:1 | `bg-brand-700` 5.41:1 |

**7개 route × 모든 텍스트 노드 = AA 위반 0.**

`warn`·`good`은 평범한 표면 위에서는 통과했고 **자기 tint 위에서만** 떨어졌다 — 그리고 그 tint 위
배지는 직전 패키지가 새로 넣은 것이다. `muted`와 같은 방식으로 토큰 하나씩 어둡게 해 모든 사용처를
한 번에 닫았다.

**어포던스:**
- `Disclosure` 컴포넌트 신설 — `list-none`으로 지운 네이티브 삼각형을 대체하는 **그려진 셰브론**
  (열리면 회전). 「필터」·「자동 분류」·「판매 계정 선택」·「AI가 확인한 내용」 네 곳이 사용한다.
- KPI 카드는 `<button>`이면서 눌려 보이지 않았다 → 라벨 옆 셰브론.
- `btn-primary` disabled가 `opacity-50`이라 **바랜 primary**로 보였다(=고장 난 것처럼) →
  `bg-canvas text-muted`로 중립화. Agent의 「물어보기」가 이제 「아직 아님」으로 읽힌다.

## 6. 하지 않은 것, 그리고 왜

**데모 hero의 「연동 테스트」 — 제외할 provenance가 없다 (보고).**
지시대로 기존 provenance를 먼저 찾았다. 결과:
- `proactive_case`에는 provenance 열이 없고 `ProactiveCaseView`에도 필드가 없다.
- 그 문의의 `inquiries.data_origin` = **`REAL`**. 운영자가 통합 테스트용으로 올린 **진짜 카페24
  게시글**이므로 합성 데이터 표식으로는 걸러지지 않는다.
- 그리고 이 org의 **열린 proactive case는 그것 하나뿐이다.** 지금 제외하면 「AI가 먼저 확인한 일」이
  통째로 사라지고, 제품 이해(A)를 벌어들인 「답변 준비됨」·「초안」이 첫 화면에서 없어진다.

새 classifier는 만들지 말라는 지시에 따라 **만들지 않았고 보고한다.** 이것은 product-owner 결정이다.

**상품 화면** — 새 metric 금지에 따라 무변경. known gap 유지. 대표 데모 경로에서 제외.
**온보딩** — backend 무변경, `ONBOARDING_LIVE_UNPROVEN` 유지. 별도 패키지에서 미연결 org로 검증.
**합성 데이터 historical cleanup** — 금지대로 하지 않음. 별도 문제로 남긴다.

## 6-b. Fresh-context 재검수, 그리고 그것이 되돌린 것

수정 후 **구현 배경을 주지 않은 새 reviewer**에게 스크린샷만 다시 줬다(§12). 판정은
**`NOT_EXECUTIVE_READY`**. 그가 새로 잡아낸 것 중 셋은 실재했고 이 패키지 안에서 닫았다.

| 지적 | 판정 | 조치 |
|---|---|---|
| 「전체 기간」 표식이 행 **끝**에 있어 5초 안에 안 읽힌다 — 0건 vs 3건은 여전히 모순으로 보인다 | 타당 | 표식을 제목 **앞**으로. 숫자의 의미를 바꾸는 span은 숫자보다 먼저 도착해야 한다 |
| **125%에서 「대신 등록하지 않습니다」가 제일 먼저 화면 밖으로 나간다** — 글자를 키운 사람일수록 보증 없이 버튼을 누르게 된다 | 타당, 그리고 심각 | 짧은 보증 **「고객에게 나가지 않습니다」**를 복사 버튼에 붙였다. 전체 문장은 아래 그대로. 등록 가능한 채널에서는 거짓 약속이므로 렌더하지 않는다 |
| 같은 문의가 목록에서 **「14시간 전」**, 패널에서 **「13시간째」** | 타당 (내가 못 본 것) | `relativeTime`이 `Math.round`, `waitedLabel`이 `Math.floor`였다. 한 타임스탬프에 반올림이 둘. `relativeTime`을 floor로 통일 — 기다린 시간을 과장하지도 않는다 |
| 「이 18건만 보기」가 outline이라 화면에서 제일 흐리다 (제일 진한 것은 「전체 4340」) | 타당 | solid로 |
| Agent의 「이미 확인해 둔 일」과 홈의 「AI가 먼저 확인한 일」이 같은 카드, 다른 이름 | 타당 | 홈과 같은 이름으로 통일 |
| 「▲397% 증가」가 무엇 대비인지 없다 | 타당 | 「이전 기간 대비 ▲397%」. 여섯 장이 각각 찍던 때 뺐던 문구인데, 이제 카드는 셋이고 delta를 가진 것은 하나라 한 줄이면 된다 |

**범위 밖이라 두고 보고한 것:** 「지켜보기 102 / 참고 4220」·「상품 지식」·「운영 정책」 등 어휘(계약이거나
별도 결정), 상품 화면, 온보딩, 합성 데이터. 그리고 채널별 표가 「홈 스크린샷에 없다」는 지적은 오해다 —
접힌 선 아래에 있고, 새 두 열은 실재한다.

**최종 verdict는 `NOT_EXECUTIVE_READY`로 남는다.** 그가 든 세 근거 중 둘은 위에서 닫았지만, 첫 번째
근거인 **「AI가 준비해 둔 유일한 일이 자기네 연동 테스트 글」**은 §6의 product-owner 결정 없이는 닫히지
않는다. 이 패키지가 스스로 EXECUTIVE_READY를 선언할 수 없는 이유다.
